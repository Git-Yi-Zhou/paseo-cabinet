## 一、 项目定位（保留）

### 1.1 一句话定位

以 **Google Antigravity 桌面端**为主控主持人（Lead），通过**官方标准 MCP** 加载本地 `paseo-cabinet` 插件，调用 **Paseo Daemon（`127.0.0.1:16767/mcp/agents`）** 的异源模型舰队，完成“多角色异质辩论 + 可追溯合议 + 机器可对账归档”的低频重决策流程。

### 1.2 三条红线（不变）

1. **不碰 OAuth、不逆向二进制、不伪造协议**：主控在第一方客户端内，桥接层只做 MCP 协议版本垫片与工具白名单转发。
2. **不做静态分叉**：`dsh-cabinet` 是唯一治理真源（当前 v0.2.6，ESM），`paseo-cabinet` 只做**薄适配**。
3. **不让主持人自证**：预算硬顶、派发台账、`events.jsonl` 全部由桥接器**代码**生成，主持人只负责叙事与合议。

### 1.3 明确移出范围（P8，沿用）

“槽位 B：主账号下指令 → 副号 `antigravity-cli` 后台跑长篇扩写”不属于本插件范围：

- 【核验】Paseo `list_providers` 实测 `antigravity` 为 `"enabled": true, "status": "error"`，错误信息 `Antigravity discovery timed out`（`~/.paseo/daemon.log` 两处独立记录一致）。
- 【推断】多账号扩大配额是否违反 Google Antigravity 附加条款，方案未做法条逐条比对，不能以“极难触发风控”充作论据。
- 结论：`paseo-cabinet` **只**调度 Kimi / Qwen / GLM / DeepSeek 四家第三方渠道；扩写需求走独立方案另行评估。

> **P1/P2 的成立前提**：正因为槽位 B 已被剥离，`paseo-cabinet` 内不再存在“非内阁的日常调用”。这条剥离是本版能够**取消“无令牌直通”、改为默认拒发**的前提——若将来重新引入日常调用，必须先恢复一条显式的旁路标记并单独审计，不得直接恢复直通。

## 三、 目标架构（P2 / P3 / P4 / P6）

### 3.1 单进程、三段落、零复制

```
Antigravity (Lead)
   │  MCP stdio
   ▼
paseo-cabinet-mcp.mjs
   ├── [1] transport       协议垫片 · 幂等性分级超时/重试 · SSE+JSON 双解析 · JSONL 线缆日志
   ├── [2] session-guard   三态令牌 · inflight 预占 · 原子提交 · 参数双向适配 · events 单点托管
   └── [3] domain          ESM 直引 dsh-cabinet 纯函数 + Canary 值级探针 + 家族归一化 + 指令改写
   │  HTTP (JSON-RPC over SSE)
   ▼
Paseo Daemon 127.0.0.1:16767/mcp/agents
   └── providers: kimi / qwen-code / glm-acp-agent / opencode(内置)
```

**为什么不拆成三个仓库包**（沿用 v1.1 的折中，并由本版 P3 补上“契约”这一层）：

- 首期**不做**跨仓独立发包（拆包 + 双宿主版本同步 + 日落治理约 1.5–2 天；现实只有两个宿主、一个用户，摊销前提不存在）。
- 但**在单文件内按 `transport` / `session-guard` / `domain` 三段组织函数与目录**，边界清晰、可单测。
- **绝对禁止**复制 `dsh-cabinet` 源码。直引方式见 3.2。

> **对“三层契约”（远 R1/R2 提案）的裁决**：内阁场 `2026-10-28-paseo-cabinet-v11-review` 中，**谋与众联合驳回**“三段各写 `*.contract.json` + 外仓固定 tag CI”（估 4.5–5.5h，占净工期三成，且 schema 仍是形状级、探不出语义漂移）——判为**优雅溢价**。**远的核心诉求（值级而非键名级）被接受**，改由 3.3 的启动期 Canary 承载：Canary 用一正一负两个真实用例实调 `checkSeatDimensions` 并断言返回值，**既是值级校验，也是可执行契约**。

### 3.2 单一真源直引（P2 / P3 / P6）

```js
// server/domain.mjs —— 唯一允许接触 dsh-cabinet 的地方
import { homedir } from "node:os";
import { pathToFileURL } from "node:url";
import { join } from "node:path";

// P6：防御未展开的占位符字面量（宿主若不展开，process.env 里就是 "${CABINET_HOME}"）
const rawHome = process.env.CABINET_HOME?.trim();
const CABINET_HOME =
  rawHome && !rawHome.startsWith("${") ? rawHome : join(homedir(), "dsh-cabinet");

const url = pathToFileURL(join(CABINET_HOME, "lib", "index.js")).href;
const core = await import(url);

// P3：REQUIRED 补全 buildInstruction / loadMinisters / loadSkills（v1.1 的 L119 漏了前三者之一）
const REQUIRED = [
  "checkSeatDimensions", "modelFamily", "TIERS", "SEAT_MAPPING",
  "MINISTER_NAMES", "loadMinisters", "loadSkills", "buildInstruction",
];
const missing = REQUIRED.filter((k) => typeof core[k] === "undefined");
if (missing.length > 0) {
  throw new Error(
    `paseo-cabinet: dsh-cabinet 导出形状不符，缺失 ${missing.join(", ")}。` +
      `请核对 CABINET_HOME=${CABINET_HOME} 与 dsh-cabinet 版本（已验证 v0.2.6）。`,
  );
}

// P3：值级 Canary —— 键存在 ≠ 语义正确
canaryCheck(core);

export const { checkSeatDimensions, modelFamily, TIERS, SEAT_MAPPING, MINISTER_NAMES } = core;
```

约束：

- 探针失败 → **响亮中止**，不静默降级、不提供半截功能。
- `ministers/*.md` **不复制**：人格文本通过 `loadMinisters()` 从 `CABINET_HOME` 直读，保证与原版同源；`skills/*.md` 则由 `scripts/setup.mjs` 转换生成（见 §7.1），既不手写也不复制。
- `audit` 子命令直接 spawn `node <CABINET_HOME>/scripts/audit.mjs <workspace>`，不重写对账逻辑。

### 3.3 启动期 Canary 值级探针（P3）

**要解决的问题**：v1.1 的探针只判 `typeof !== "undefined"`。据在 R2 一手核实——上游若把 `checkSeatDimensions` 的入参从 `{temperament, stance}` 改名、或把返回从 `{pass, failures}` 改成布尔，键名探针**全部照过**，而运行期要么静默放行、要么 `undefined < 2` 恒真拦截。

```js
// server/domain.mjs
const CANARY_SEATS = [
  { seat: "红队批判官", temperament: "攻击", stance: "共识是错的", model: "moonshot/k3", isRedTeam: true },
  { seat: "正方",       temperament: "辩护", stance: "建设",       model: "zhipu/glm-5.3" },
  { seat: "成本官",     temperament: "读者", stance: "三秒划走",   model: "deepseek/flash" },
];

function canaryCheck(core) {
  const ok = core.checkSeatDimensions(CANARY_SEATS, "google/gemini-4-argon");
  if (!ok || ok.pass !== true || !Array.isArray(ok.failures)) {
    throw new Error("paseo-cabinet Canary 失败：正向用例未通过（返回形状不符或语义变更）");
  }
  const sameTemp = CANARY_SEATS.map((s) => ({ ...s, temperament: "同质" }));
  const bad = core.checkSeatDimensions(sameTemp, "google/gemini-4-argon");
  if (!bad || bad.pass !== false || !bad.failures.some((f) => f.includes("气质维"))) {
    throw new Error("paseo-cabinet Canary 失败：负向用例未触发（硬闸已失效）");
  }
  // 红队同源负向
  const sameFamily = CANARY_SEATS.map((s) => ({ ...s, model: "google/gemini-4-argon" }));
  const red = core.checkSeatDimensions(sameFamily, "google/gemini-4-argon");
  if (red.pass) throw new Error("paseo-cabinet Canary 失败：红队同源未被拦截");
}
```

三条断言分别锁住 **返回值形状 / 气质维 / 红队异源** 三处最易被上游重构打穿的语义。**每次开阁自动跑，失败即拒绝启动**（fail-closed）。

### 3.4 真实模型家族归一化（P3，升级为“模型特征优先 + Provider 别名兜底”）

**要解决的问题**：`checkSeatDimensions` 内部用 `modelFamily()` 取第一个 `/` 之前的字符串（`lib/index.js:109-112`）。若按 v1.1 的 `${provider}/${model}` 拼装，不仅 `opencode` 这个**聚合 CLI** 会把真实厂商完全吞掉，而且实测本机 `list_models` 发现 **`kimi`（含 `Zhipu AI Coding Plan/glm-5.3`）与 `qwen-code`（含 `deepseek-v4.1-flash(openai)`、`glm-5.3(openai)`）同样挂载了跨厂模型**【核验】！

```js
modelFamily("opencode/google/gemini-2.5-pro") === "opencode"   // 【核验】实跑
modelFamily("opencode/deepseek/deepseek-flash") === "opencode" // 【核验】实跑
modelFamily("qwen-code/glm-5.3(openai)") === "qwen-code"       // 【核验】跨厂挂载被吞
```

后果有二，且方向相反：① 红队若经聚合器承载 google 系模型，**同源却被判异源通过**（漏检）；② 两席分别用不同渠道的同厂模型（如 `glm-acp-agent/glm-5.3` 与 `qwen-code/glm-5.3(openai)`）或同渠道的异厂模型时，家族判定失真。

```js
// server/domain.mjs
const MODEL_VENDOR_PATTERNS = [
  [/\b(gemini|google)\b/i, "google"],
  [/\b(glm-|zhipu|zai)\b/i, "zhipu"],
  [/\b(deepseek)\b/i, "deepseek"],
  [/\b(qwen|coder-model)\b/i, "qwen"],
  [/\b(kimi|moonshot|k3|k2)\b/i, "moonshot"],
  [/\b(claude|anthropic)\b/i, "anthropic"],
  [/\b(gpt-|o3|codex|openai)\b/i, "openai"],
  [/\b(mimo|xiaomi)\b/i, "xiaomi"],
];

const FAMILY_ALIASES = {
  "kimi": "moonshot", "kimi-code": "moonshot", "kimi-coding": "moonshot",
  "qwen-code": "qwen", "qwen-token-plan-cn": "qwen", "qwen": "qwen",
  "glm-acp-agent": "zhipu", "zai-coding-cn": "zhipu", "glm": "zhipu",
  "deepseek-account": "deepseek", "deepseek": "deepseek",
  "google": "google", "gemini": "google", "antigravity": "google",
  "xiaomi-token-plan-cn": "xiaomi", "mimo": "xiaomi",
};

export function canonicalModelFamily(provider, model) {
  const m = String(model ?? "").trim();
  // 1) 优先从 model ID 识别真实底层厂商（去掉 "(openai)" 等协议后缀干扰后再匹配）
  const cleanedModel = m.replace(/\([a-z0-9_-]+\)$/i, "");
  for (const [re, vendor] of MODEL_VENDOR_PATTERNS) {
    if (re.test(cleanedModel)) return vendor;
  }
  // 2) 未命中模型特征时回退查 provider 别名表
  const p = String(provider ?? "").trim().toLowerCase();
  const prefix = m.includes("/") ? m.split("/")[0].trim().toLowerCase() : p;
  return FAMILY_ALIASES[prefix] ?? FAMILY_ALIASES[p] ?? `unknown:${p}`;
}

/** 喂给 checkSeatDimensions 的路由：`<family>/<model>`，其内部 modelFamily() 恰好取到 family */
export function gateRoute(provider, model) {
  return `${canonicalModelFamily(provider, model)}/${model}`;
}
```

**未知 provider 的处理**：`FAMILY_ALIASES` 未命中的 provider **不得静默取原值当家族**——必须按“家族未知”处理，等同一个未注册的独立家族（即计数时算作“独立一家”，但不参与任何“同源”判定），并在 disclosure 标注“家族未归一化：`<provider>`”，同时提示补 `FAMILY_ALIASES`。

## 四、 `cabinet_start` 规格与组阁前交互确认规程（P1 / P3 / P5 / P9）

### 4.1 入参

| 参数 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `topic` | string | ✅ | 议事议题 |

> **`gateOverride` 裸布尔被废的原因**（P1）：本机 `config.json` 的 `autoExecutionPolicy` 为 `CASCADE_COMMANDS_AUTO_EXECUTION_EAGER`【核验】——主控在收到 `PRINCIPLE_VIOLATION` 后完全可能“为了完成任务”自行重调 `cabinet_start(gateOverride: true)`，使“用户主权放行”变成“LLM 自审自放”。改为**一次性随机码**后，放行必须同时满足“主持人知道码”+“用户说过误拦恢复”，且 `gate_overrides` 计数与大写审计烙印不可绕过。

### 4.2 执行顺序（代码内，非 LLM 心算）

1. **合并默认钉扎与用户改定（P9）**：先加载 `config/ministers.json` 的默认钉扎表（`provider`、`model`、`reasoningEffort`、`thinkingOptionId`），若传入 `overrides` 则逐阁员键覆盖对应字段。
2. **在线预检与思考档位核验（P5 / P9）**：
   - 实时调 Paseo `list_providers` 与 `list_models(provider)`；
   - **默认钉扎分支**：若默认钉扎不可用 → 按 `pool` 顺序取第一个**在线、本场未用、且家族未撞**的异源路由自动替换，记录 `fallback: {seat, pinned, actual, reason}`；
   - **用户显式改定分支（`overrides`）**：若 CLI 非 `available`、模型不在目录内、或 `thinkingOptionId` 不在该模型的 `thinkingOptions[]` 内 → **绝不静默替换**，直接进 `violations[]` 并附带实际合法选项列表。
3. **同场撞车处理（P5 / P9）**：
   - 默认钉扎撞车 → 后者按 `pool` 自动错开；
   - 用户显式改定撞车 → **保留用户指定但触发 `warnings: ["同场模型撞车：…"]`**，由主持人提醒并提供错开建议。
4. **三维不重合与组阁原则硬闸（P2 直引 + P3 归一化 + P9）**：
   ```js
   const seats = resolveSceneSeats(scene, tier, roles, pinning, overrides); // 见下
   const gateSeats = seats.map((s) => ({ ...s, model: gateRoute(s.provider, s.model) }));
   const { pass, failures } = checkSeatDimensions(gateSeats, gateRoute(hostFamily, hostModel));
   ```
   - **`resolveSceneSeats()` 是 v1.2 新增的必需件**：把“场景 + 档位 + 自定义席位 + 钉扎表”翻译成确定性的席位数组（每项含 `seat` / `minister` / `provider` / `model` / `reasoningEffort` / `thinkingOptionId` / `temperament` / `stance` / `isRedTeam`）。**原版 `SEAT_MAPPING` 只是展示用数组，不承担解析**——v1.1 把它当成解析器是误读，`dsh-cabinet` 从未导出该能力【核验：`lib/index.js:91-101`】。
   - 同时检查“同一专职阁员兼任两席”或“移除红队固定席”。
   - 若 `pass === false` 且无有效 `gateOverrideToken` → **拦截组阁**（`ok:false`，`status:"PRINCIPLE_VIOLATION"`，令牌置 `BLOCKED`），返回结构化 `violations[]` 与 `suggestions[]`。
5. **令牌签发（P1）**：
   ```json
   {
     "sessionId": "2026-10-28T19-40-00-paseo-cabinet-plan-review",
     "state": "STAGED",
     "tier": "advanced",
     "cap": 16,
     "used": 0,
     "inflight": 0,
     "archiveDir": "<workspace>/.cabinet/<sessionId>",
     "hostFamily": "google",
     "agentIds": [],
     "thinkingOptionIds": { "feng": "high", "yuan": null, "gu": "max", "zhong": "max" },
     "violations": [],
     "gateOverrides": 0,
     "createdAt": "2026-10-28T19:40:00+08:00",
     "activatedAt": null,
     "closedAt": null,
     "ttlExpiresAt": "2026-10-28T21:40:00+08:00"
   }
   ```
   落盘：`~/.paseo/cabinet-sessions/<sessionId>.json`（桥接器私有，主持人只读引用）。**`STAGED` 阶段不创建 `.cabinet/<sessionId>/` 目录**（散会不留幽灵目录）。
6. **返回编排计划**：直引 `buildInstruction(...)` → **经 `adaptInstructionForPaseo()` 改写**（P4，见 4.4）→ 映射为 9 工具与 `cabinetSessionId` 令牌说明 + 披露卡数据（逐席 `CLI / 模型 / 思考档位 / 钉扎=实际？`、`violations[]`、`warnings[]`、预算、当前 `state`）。

> **令牌不是“信任凭证”，而是“作用域标记 + 状态机”**：主持人拿到 `sessionId` 只能引用；额度、`used`、`inflight`、`archiveDir`、`state` 全部由桥接器持有，主持人无法伪造也无法自行激活。

### 4.3 正式组阁前的“默认钉扎披露 → 三要素改定 → 违规提醒”交互闭环（P9，强制停等点 1）

在调用 `create_agent` 正式派发任何阁员之前，主持人**必须严格执行**：

1. **第一步：先亮默认钉扎表并停等确认（此时令牌为 `STAGED`）**
   ```markdown
   ## 组阁前默认钉扎表（待你确认或改定）
   议题：... ｜ 场景：writing ｜ 档位：standard（4 席 × 1 轮，硬顶 9 次调用）

   | 席位 | 阁员 | CLI (`provider`) | 模型 (`model`) | 思考强度 | 该模型 Paseo 实测可选档位 | 钉扎=实际？ |
   | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
   | 红队批判官（固定席） | 锋 | `kimi` | `kimi-code/k3.1-pro` | `high` | `low / high / max` | ✅ 默认钉扎 |
   | 立意官 | 远 | `qwen-code` | `qwen3.8-max(openai)` | `内置默认 (null)` | `（无独立档位，自适应思考）` | ✅ 默认钉扎 |
   | 结构官 | 骨 | `glm-acp-agent` | `glm-5.3` | `max` | `minimal / low / medium / high / xhigh / max` | ✅ 默认钉扎 |
   | 读者代理 | 众 | `opencode` | `deepseek/deepseek-flash` | `max` | `none / low / high / max` | ✅ 默认钉扎 |

   - 组阁原则检查：✅ 红队异源（vs 主控 google） ｜ ✅ 真实模型家族 4 家 ｜ ✅ 气质维/立场维不重合
   - 令牌状态：`STAGED`（未确认，不可派发）
   ```
   随后调用 `ask_question` 停等：
   - **选项 1：`确认开议（按上表正式组阁并派发 R1）`**
   - **选项 2：`修改阁员配置（我将指定要修改的席位/CLI/模型/思考档位）`**
   - **选项 3：`散会（取消本次内阁）`**

2. **第二步：按用户指令修改三要素**
   主持人不得直接派发，而是把修改项填入 `overrides` 并**带同一 `sessionId`** 重调 `cabinet_start`（返回新披露卡，令牌仍为 `STAGED`）。

3. **第三步：违背组阁原则时主动拦截并提醒**
   输出《⚠️ 组阁原则冲突提醒》，逐条给出违规原因与建议：
   - **类型 A（红队异源违反）**：红队与主控同属一真实家族（**用 `canonicalModelFamily` 判定，不是 provider 字面量**）；
   - **类型 B（模型维全重合）**：全场真实家族 <2；
   - **类型 C（同场同模型撞车）**：两席 `provider + model` 完全相同；
   - **类型 D（专职阁员重席 / 移除红队固定席）**；
   - **类型 E（CLI 离线 / 模型不存在 / 思考档位不支持）** —— **物理不可执行故障**。

   提醒后再次 `ask_question`：**① 按建议重新调整**、**② 恢复默认钉扎**、或 **③ 显式误拦恢复（我确认按当前配置继续）**。

   > **P1 硬约束：类型 E 不可被误拦恢复放行。** A–D 属“原则争议”，用户有权裁量；E 属“这台机器上跑不起来”，放行只会让 `create_agent` 当场失败并白白消耗 `used`。E 必须回到确认环节重选。

4. **第四步：确认开议才激活**
   `cabinet_start({ sessionId, confirm: true, cardReaction: "confirm" })` → 令牌 `STAGED → ACTIVE`，此时才创建 `.cabinet/<sessionId>/` 与 `events.jsonl` 首行，写 `intake`/`setup`/`steering` 事件。**未获此调用，桥接器拒绝任何 `create_agent`。**

### 4.4 `adaptInstructionForPaseo()` 指令改写层（P4）

`buildInstruction()` 输出的是 **dsh 宿主**的编排计划，其中有四处会直接毁掉本架构：

| # | 原版指令（`lib/index.js`） | 直引不改的后果 | v1.2 改写 |
| :-- | :--- | :--- | :--- |
| 1 | `subagent(run_in_background: true)`（L434-435） | 宿主无此工具，主持人报错或幻觉 | → `create_agent`，并注明“每次调用 = 1 个 Agent，4 席 = 4 次调用” |
| 2 | `send_message` / `list_subagent_models` / `ask_user_question` / `skill`（多处） | 工具名全部不存在 | → `send_agent_prompt` / `list_providers`+`list_models` / `ask_question` / **角色卡全文已内嵌，无需加载** |
| 3 | **“用你自己的文件工具在项目工作区写入 … `events.jsonl` … 必记三类事件：①派发——event 以 `dispatch:spawn` 开头且带 `delegationId`”（L586-599）** | 主持人用 `write` 覆盖 = 抹掉桥接台账；用追加 = `dispatch` 行翻倍，`audit.mjs` 报 `2N vs N` **必失败** | → **删除整段写 `events.jsonl` 的指令**，替换为“归档只写 `round-N.jsonl` 与 `protocol.json`，然后调用 `cabinet_audit(sessionId)`；`events.jsonl` 由桥接器独占写入” |
| 4 | “归档后跑一次 `node scripts/audit.mjs`” | 主持人无 shell 保证，且会绕过 `cabinet_audit` 的 GC 与回填 | → `cabinet_audit(sessionId)` |

**实现纪律**：改写采用**带断言的关键字替换**，每个目标片段若未命中 → **抛错中止**（`throw new Error("adaptInstruction: 未命中片段 <id>，dsh-cabinet 版本可能已漂移")`）。**禁止“找不到就原样放过”**——静默放过正是 V-02 那类漏洞的温床。

## 五、 三态令牌与预算硬顶（P1 / P2）

### 5.1 令牌状态机

```
                 cabinet_start(topic)                      用户确认开议
    ┌────────┐  ─────────────────►  ┌──────────┐  ─────────────────►  ┌────────┐
    │ (无)   │                      │  STAGED  │                      │ ACTIVE │
    └────────┘                      └──────────┘                      └────────┘
                                          │                                 │
                       闸拦截 / 改定违规  │                                 │ 散会 / 审计
                                          ▼                                 ▼
                                    ┌──────────┐                     ┌──────────┐
                                    │ BLOCKED  │                     │  CLOSED  │
                                    └──────────┘                     └──────────┘
```

| 状态 | 可派发？ | 说明 |
| :--- | :--- | :--- |
| `STAGED` | ❌ | 仅用于披露预览与改定重算；不建归档目录；调用 `create_agent` 返回 `CABINET_SESSION_NOT_ACTIVE` |
| `ACTIVE` | ✅ | 唯一可派发状态；计入 `used`/`inflight` |
| `BLOCKED` | ❌ | 三维/红队硬闸拦截或改定违规；需重新确认或散会 |
| `CLOSED` | ❌ | 已散会或已审计；`ttlExpiresAt` 后自动清理 |

### 5.2 执法点：`create_agent` / `send_agent_prompt`

```
收到调用
  ├─ 无 cabinetSessionId？
  │    └─ 【P1】拒发，错误码 CABINET_SESSION_REQUIRED
  │         （附提示：若确需非内阁调用，请禁用本插件或走独立 Paseo MCP 入口）
  └─ 带 cabinetSessionId →
       ├─ 令牌不存在/已过期 → 拒发 CABINET_SESSION_INVALID
       ├─ state !== "ACTIVE" → 拒发 CABINET_SESSION_NOT_ACTIVE（附当前 state）
       ├─ used + inflight >= cap → 拒发 CABINET_BUDGET_EXCEEDED
       └─ 通过 →
            [1] 加锁：inflight += 1（预占）
            [2] 参数适配：剥离 cabinetSessionId / cabinetPhase；
                create_agent 注入只读模式与 thinkingOptionId
            [3] 锁外并发：转发 Paseo（超时/重试按 5.3 分级）
            [4] 加锁提交：
                成功 → inflight -= 1; used += 1;
                       同一同步块内 append events.jsonl（dispatch:*）;
                       登记 agentId 到 agentIds[]；持久化会话 JSON
                失败 → inflight -= 1;（used 不变、events 不写）
  └─ 结束
```

**记账与硬顶是同一机制的两个出口**：一次成功派发必然同时产生“`used` +1”“一行 `dispatch` 事件”“一个 `agentId` 登记”，三者在同一临界区内完成，不存在只发生其一的中间态。

- 计数器**持久化**在会话 JSON 中，Daemon 重启不清零；重启后凭 `sessionId` 继续累计。
- **`inflight` 不落盘**：进程崩溃时 `inflight` 归零，可能造成“实际已派但未计入 `used`”的偏差——这部分由 `cabinet_audit` 的 `list_agents` 对账兜底（见 P7），并在 `disclosure` 标注 `inflight_lost`。
- **并发安全**：锁只包住内存/磁盘的额度读写（微秒级），**网络 I/O 在锁外**。这样 R1 四席仍是真并发，不会退化成串行排队。

### 5.3 传输层：按幂等性分级（P2）

| 工具 | 幂等 | 超时 | 自动重试 | 理由 |
| :--- | :--- | :--- | :--- | :--- |
| `list_providers` / `list_models` / `list_agents` / `get_agent_activity` | ✅ | 10s | 1 次 | 只读，重发无副作用 |
| `create_agent` | ❌ | **60s** | **0 次** | 重发会拉起**两个**子 Agent 并双倍计费 |
| `send_agent_prompt` | ❌ | **60s** | **0 次** | 重发会让同一席回答两遍并污染 R2 材料 |
| `delete_agent` | ⚠️ 近似幂等 | 30s | 0 次 | 失败由 GC 的 `gc_failed` 记录并重试一次人工触发 |

**超时后不猜**：报错文案强制要求“先调 `list_agents` 对账，确认无残留后再决定重派”，并把该次调用记为 `unknown`（写 `events.jsonl` 的 `status` 字段，但**不**计入 `cost.calls`），由人工/`cabinet_audit` 收敛。

**响应解析必须双通道**：v1.1 沿用的 `mcp-bridge.mjs` 只处理 `rawLine.startsWith("data: ")` 的行——**纯 JSON 的 JSON-RPC 错误包会被静默丢弃，客户端永久挂起**。v1.2 的 `transport.mjs` 必须：

```js
// 1) 先尝试整体 JSON.parse
// 2) 失败则按 SSE 逐行取 "data: " 前缀
// 3) 两者都失败 → 回一个 JSON-RPC error（带原响应前 512 字符），绝不静默
```

### 5.4 预算数值（直引 `TIERS`）

| 档位 | 席位 × 轮次 | 调用轨硬顶 | token 参考轨 | 升档方式 |
| :--- | :--- | :-- | :-- | :--- |
| `standard` | 4 × 1 | 9 | 19,000 | — |
| `advanced` | 5 × 2 | 16 | 54,000 | 带同一 `sessionId` 重调，`cap: 9 → 16`，`used` 延续、`archiveDir` 不变 |
| `max` | 6 × 2 | 19 | 65,000 | 同上 `→ 19` |

> 硬顶公式：`cap = 名义 + 一整轮重派 + 1`。触顶行为：**拒发并返回部分议定书**，不追加委派、不询问用户。
>
> **token 轨的诚实口径**（P8 回应众 R1 的“没秤却报精确斤两”）：`19K / 54K / 65K` 是 `TIERS` 里的**设计常量**（`config/tiers.json`），**不是实测值**。v1.2 在 `cost.tokens_est` 中必须写明“接口口径估算，子智能体内部读取不可观测”，并在 `index.jsonl` 新增 `tokens_measured: null` 占位，直到 D5 拿到真实测量再回填。

## 六、 R2 续谈安全契约与进程回收（P6 / P7）

### 6.1 续谈为受控特性，非默认卖点

| 项 | 规定 |
| :--- | :--- |
| 开关 | `config/continuation.json` 或环境变量 `CABINET_CONTINUATION=1`；**首期默认关闭（冷启动）** |
| TTL | 会话 10 分钟无活动视为失活（与 `lib/index.js:519-522` 的 TTL 条款一致） |
| 兜底 | `send_agent_prompt` 返回失败/超时/会话不存在 → **自动退回 `create_agent` 冷启动**，简报内嵌该席 R1 原文，计入 `reassigns` **且计一次 `used`**（回退也是一次真实派发） |
| 可重放性 | 只要本场动用过续谈，`protocol.json` 强制 `"replayable": false`；纯冷启动场次为 `true` |
| 提示词 | 首期不得声称“省 40% Token”；实测前只写“续谈可减少重复简报，幅度待测” |

### 6.2 `cabinet_audit` 固化五步顺序（P7）

v1.1 让 `cabinet_audit` “顺带 GC”并把 `gc_failed` 写回 `protocol.json`，但 `audit.mjs` 必须**在 `protocol.json` 已落盘后**才能跑——顺序未定就会死锁或需二次重写。v1.2 固化：

```
cabinet_audit(sessionId):
  ① GC       : 对本场 agentIds[] 逐个 delete_agent（不存在的跳过）
                 失败项收集为 gcFailed[]
  ② 回填     : 若 protocol.json 已存在 →
                 把桥接器真实 used 对照 cost.calls（不等则校正并记 deviation）
                 把 gcFailed 写入 disclosure
  ③ 补事件   : 追加 events.jsonl 的 cost / close 事件（含 used、cap、unused、reassigns）
  ④ 对账     : spawn node <CABINET_HOME>/scripts/audit.mjs <workspace>
                 解析 stdout，**必须匹配行** `^<sessionId>:\s*ok\s+calls=(\d+)`
                 ├─ 未匹配（WARN 跳过 / mismatch / 本场未出现）→ 判「未通过」
                 └─ 匹配且 calls == cost.calls → 判 ok
  ⑤ 写回     : 追加/更新 <workspace>/.cabinet/index.jsonl 一行
                 令牌 state = "CLOSED"
```

**为什么要精确匹配行**：`audit.mjs` 会扫描 `.cabinet/` 下**全部**子目录，且对“无 `dispatch` 行”“`cost.calls` 非数值”只打 `WARN` 后 `continue`（退出码仍为 0）。据在 R2 实跑发现：本工作区 `2026-10-09` 旧档为 `declared=8 vs events=2`、`exit 1`——**只看退出码会把历史坏档当成自己失败，也可能把本场的空档当成通过**。精确匹配 `sessionId` 行是唯一可靠的判据。

**超时/散会路径的 GC**：`cabinet_start(adjourn: true)` 或启动时发现 `ttlExpiresAt` 已过的会话，桥接器自动执行 `agentIds[]` 回收，避免“R1 速览后散会”留下 4 个僵尸子 Agent。

### 7.3 `mcp_config.json`（生成物，P6）

```json
{
  "mcpServers": {
    "paseo-cabinet": {
      "command": "<setup.mjs 探测到的 node 绝对路径>",
      "args": ["<插件绝对路径>/server/paseo-cabinet-mcp.mjs"],
      "env": {
        "CABINET_HOME": "<setup.mjs 探测到的 dsh-cabinet 绝对路径>",
        "PASEO_ENDPOINT": "http://127.0.0.1:16767/mcp/agents"
      }
    }
  }
}
```

**为什么必须是生成物**：v1.1 声称“`paths.mjs` 在运行期解析 `command` 与 `${PLUGIN_DIR}`”——**这在时序上不可能**。`mcp_config.json` 是 **Antigravity 宿主在拉起子进程之前**读取的，此时 Node 进程尚未存在，`paths.mjs` 没有机会执行。宿主若不展开占位符，`spawn "${PLUGIN_DIR}/..."` 直接 `ENOENT`。

`scripts/setup.mjs` 的探测顺序：

1. `command`：`process.execPath`（即当前跑 `setup.mjs` 的 Node）→ `DSH_NODE` 环境变量 → `PATH` 查 `node`/`node.exe`；三者皆无 → **报错并要求安装 Node ≥ 20**（不猜）。
2. `PLUGIN_DIR`：`dirname(dirname(fileURLToPath(import.meta.url)))`。
3. `CABINET_HOME`：`CABINET_HOME` 环境变量（且**不以 `${` 开头**）→ `os.homedir()/dsh-cabinet` → 报错并提示 `git clone`。
4. `PASEO_ENDPOINT`：`PASEO_ENDPOINT` 环境变量 → 读 `~/.paseo/config.json` 的 `daemon.listen` 拼接 → 兜底 `http://127.0.0.1:16767/mcp/agents`。

**运行期仍要防御**：`domain.mjs` 里那段 `!rawHome.startsWith("${")` 不是冗余——它是“用户手改了 `mcp_config.json` 或宿主行为变更”的兜底，成本 1 行。

| **D5** | **故障演练 + 续谈对比** | ① 杀 Daemon 再拉起，令牌仍有效、`used` 不清零；② 伪造过期令牌被拒；③ **模拟超时丢包**：断言 `used` 未增、`events` 未写、报错提示对账；④ `send_agent_prompt` 失败触发冷启动回退并计 `reassigns` + 1 次 `used`；⑤ 未确认 `STAGED` 令牌散会 → 无残留目录、无残留 Agent；⑥ 同议题冷启动 vs 续谈各 1 次，记录真实 token 与时长写入 `docs/token-baseline.md` | 1.5h |

**合计 9h**（区间 8–9.5h，取决于 D1 探字段耗时）。

**回滚方案**：禁用插件（`JetboxWriteState` 或设置页开关）即整体下线，宿主无残留改动；桥接器为纯增量，不注册任何系统级服务。**卸载时** `rm -rf ~/.paseo/cabinet-sessions/` 清空令牌。

| R-08 | 首次安装误以为免重启 | 用户直接开阁 | 工具不出现 | README 首屏 + 议定书均写明“首次需重启一次” | 极低 |

> **R-09 是 P1 的代价，必须写明**。内阁场 `2026-10-28-paseo-cabinet-v11-review` 中，**众**的保留意见即此：单用户低频场景下，为了堵死“漏传令牌逃逸”而全局拒发，会让“开了插件顺手派个 Agent 写稿”变成需要先关插件。本版接受该取舍——理由是“日常扩写”已由 P8 剥离，且“硬顶可被主持人摘除”是更严重的问题。
